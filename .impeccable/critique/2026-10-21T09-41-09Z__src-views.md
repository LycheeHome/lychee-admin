## Overall Impression

The diagnosis loop is now genuinely strong: list pill to failing hop to a copyable command in about 15 seconds. Ember lands only where an action will work. What remains is drift between the page and the system it describes:
- copy that still promises a compose file;
- a retired site that looks identical to a new one;
- one control wearing different emphasis on different pages;
- explanatory sentences set in machine mono.

The biggest opportunity is making retired a visible state, because its one useful action, Prune, is buried about 2,000px down.

## What's Working

1. **Hop chain plus What to check** (hopFixes). Two clicks and zero guessing from a red pill to a runnable command. This answers PRODUCT.md's "which hop broke" job directly.
2. **The add-site preview.** The same writers run in preview and submit, the full diff is shown, and skipped steps are marked. "Fail closed, in order" is visible before anything is written.
3. **Status and emphasis discipline.** Every colour carries a word, neutral states stay neutral, and Visit drops out of Ember when the site isn't serving.

## Priority Issues

**[P1] The add-site copy contradicts how Next.js sites work.**
- **What:**
  - The framework option reads "Next.js — generates a Dockerfile + docker-compose.yml" (html.ts:265). The scaffold is Dockerfile, .dockerignore and release.yml, there is no compose file, and add-site writes none of them.
  - The Reverse proxy description ("a process you already run… won't start, stop, or restart") still shows when Next.js is picked, though the reconciler does run that container.
  - The preview panel beside it says the opposite.
- **Why it matters:** This is the one place the app promises work it doesn't do. It breaks "never blur automated and manual" on the page where the decision is made.
- **Fix:**
  - Change the option to "Next.js — built from its own repository; the reconciler runs the container".
  - When a framework is chosen, swap or annotate the reverse-proxy description.
- **Suggested command:** /impeccable clarify

**[P1] A retired declaration is invisible until deep in the page.**
- **What:**
  - gone.lychee.land reads NOT DEPLOYED in the list and the pill, the same as a never-attached site.
  - The "retired (state: absent)" warning and Prune sit inside runbook step 3, below about 1,800px of scaffold files, with Manual steps first.
- **Why it matters:** The page's one useful action is hidden behind content that's irrelevant to it, and nothing in the list distinguishes the site.
- **Fix:**
  - Lift the retired notice and Prune to the top of the From a repository card, or under the request path.
  - Decide in DESIGN.md whether retired becomes a status word.
- **Suggested command:** /impeccable layout

**[P2] One control, different emphasis per page.**
- **What:**
  - Deploy is filled Ember in runbook step 4 but an outline on an installed card and on the board.
  - Prune is Primary on the site page but Secondary on the board.
  - The read-only "X available" label is Ember Light (text-rose-300, html.ts:1338).
- **Why it matters:** The same action reads as more or less important depending on location, and an Ember-tinted value weakens the Ember Is Interactive Rule.
- **Fix:**
  - Set "available" in Smoke or Chalk mono.
  - Write down the step-4 exception, or unify.
- **Suggested command:** /impeccable polish

**[P2] Explanatory sentences set in mono.**
- **What:** Each of these is a full sentence set in mono:
  - the board's "lychee-admin couldn't read this container's state." (SERVICE_DETAIL, html.ts ~1585);
  - the Prune caption (html.ts:850);
  - the add-site error box.
- **Why it matters:** This breaks the Mono-Carries-Facts Rule, and on the board human explanations look like gate strings. It feeds the flat hierarchy the detector flagged on /services.
- **Fix:** Use Body (Nunito, Smoke) for explanations; keep mono for gate strings, tags and paths.
- **Suggested command:** /impeccable typeset

**[P2] The add-site error is said twice, differently.**
- **What:** Port 2019 shows "Already in use by reserved (Caddy admin API)" on the field (app.js:384, ungrammatical) and "Port 2019 is reserved (used by lychee-admin itself or Caddy's admin API)" in the panel (siteValidation.ts:141). The panel hedges between two owners the client already knows apart.
- **Fix:** One message, one owner, in the field; the panel says "Fix the port above."
- **Suggested command:** /impeccable clarify
