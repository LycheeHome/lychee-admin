# Tailwind CSS Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-rolled `public/style.css` with a generated Tailwind CSS v4 stylesheet, and rewrite `src/views/html.ts` to use Tailwind utility classes for a restyled dark theme (warm stone base, rose-400 accent).

**Architecture:** Tailwind v4's standalone CLI (`@tailwindcss/cli`) compiles `src/styles/tailwind.css` to `public/style.css` as a build step — no PostCSS config. `npm run dev` runs that CLI in `--watch` mode alongside the existing `tsx watch`, via `concurrently`. `src/views/html.ts` is rewritten in place: every custom CSS class it currently emits is replaced with Tailwind utility classes, except the two classes `public/app.js` selects directly (`.delete-form`, `dialog.modal`), which are kept as behavioral hooks alongside the new utility classes.

**Tech Stack:** `tailwindcss` + `@tailwindcss/cli` (v4, CLI-only, no PostCSS/autoprefixer), `concurrently` (dev-only, runs two watchers side by side).

## Global Constraints

- No `postcss`, `autoprefixer`, or `postcss.config.js` — Tailwind v4's CLI handles prefixing/minification/nesting natively and nothing in scope needs a plugin it doesn't already cover.
- `public/style.css` becomes a generated build artifact: gitignored, never hand-edited again, regenerated by both `npm run build` and `npm run dev`.
- Visual direction: dark theme, Tailwind's default `stone` scale as the neutral base, `rose-400` as the single accent color, `red` scale for danger/error states (kept visually distinct from the rose accent).
- Fonts stay as-is: Poetsen One (headers, via a new `font-display` utility) and Nunito (body, via overriding the built-in `font-sans` token) — the one piece of the design *not* reset to Tailwind defaults. Google Fonts `<link>` tags in `layout()` are unchanged.
- `public/app.js` is not modified. It selects `.delete-form` and `dialog.modal` by class name (plus several `data-*` attributes that aren't changing) — `html.ts` must keep emitting those two exact class names.
- No change to `src/lib/*`, `src/routes/*`, `src/middleware/*`, or any server-side logic — this is a views/styling-only change.
- No test suite covers views today; verification is `npm run build` (tsc + tailwindcss both compile clean), `npm run typecheck`, and `npm run lint` passing. Per standing project preference, do not run `npm run dev` — the user verifies the restyled UI themselves in a browser.

function escapeHtml(value: string): string {
  return value
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;");
}
