# Bump actions/checkout pin to v7

## Problem

Both `.github/workflows/deploy.yml` and the GitHub Actions workflow template
generated by `src/lib/frameworkScaffold.ts` pin `actions/checkout@v4`. The
current latest major release is `v7.0.1` (confirmed via `gh api
repos/actions/checkout/releases/latest`, published 2026-07-20) — three major
versions behind.

## Design

Change `actions/checkout@v4` to `actions/checkout@v7` in both places:

- `.github/workflows/deploy.yml` — this repo's own CI/CD workflow.
- `src/lib/frameworkScaffold.ts`'s `nextjsDeployWorkflow` template — the
  workflow text generated for a user to paste into their own Next.js app's
  repo.

Still a major-version tag pin (not "latest"/unpinned), matching the
reasoning already established for this project: a moving major-version tag
gets non-breaking updates automatically while avoiding the risk of an
untested commit on the action's default branch silently breaking the
pipeline.

No other change — this is a pure version-string bump, not a workflow
redesign. Nothing about what the workflows *do* changes.

## Out of scope

- No investigation into whether `actions/checkout`'s v4→v7 changes affect
  anything this project's workflows rely on (e.g. Node version requirements
  for the runner) — the self-hosted runner already runs current Node via
  `actions/setup-node@v4` with `node-version: 22` in `deploy.yml`, and
  `checkout` itself has no meaningful surface this project depends on
  beyond "clone the repo," so this is treated as a safe, mechanical bump.
