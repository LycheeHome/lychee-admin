# Push a tag like v1.2.3 to build and publish ghcr.io/<owner>/<repo>:1.2.3.
# The tag is plain X.Y.Z, which is the only form the host's reconciler
# recognises; the build step refuses anything else. The
# source label links the package to this repo, so the
# package inherits the repo's access rather than needing its own.
name: release

on:
  push:
    tags:
      - "v*.*.*"

permissions:
  contents: read
  packages: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      - name: Log in to ghcr.io
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: echo "$GITHUB_TOKEN" | docker login ghcr.io -u "$GITHUB_ACTOR" --password-stdin

      - name: Build and push
        run: |
          IMAGE="ghcr.io/${GITHUB_REPOSITORY,,}"
          VERSION="${GITHUB_REF_NAME#v}"
          if ! [[ "$VERSION" =~ ^(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$ ]]; then
            echo "::error::Tag $GITHUB_REF_NAME is not deployable: only plain vX.Y.Z tags (no leading zeros, no pre-release suffix) are offered for deploy."
            exit 1
          fi
          docker build --label org.opencontainers.image.source="https://github.com/$GITHUB_REPOSITORY" -t "$IMAGE:$VERSION" .
          docker push "$IMAGE:$VERSION"

Manual steps

Nothing on this page does these for you.

1

Create the DNS record, once per hostname: in the Cloudflare dashboard, add a proxied CNAME named preview pointing at the target below. Until it exists, the site can't be reached from the internet even while every check on this page passes: lychee-admin checks lychee itself, never Cloudflare.

11111111-2222-3333-4444-555555555555.cfargotunnel.com

Or, from a machine with a Cloudflare login — the host keeps no account certificate, so run cloudflared tunnel login first:

cloudflared tunnel route dns 11111111-2222-3333-4444-555555555555 preview.lychee.land

Danger

Removing takes the site out of the Caddyfile and the tunnel route, reloads Caddy, then restarts the sites tunnel. It then retires the site's declaration, which stops its container. lychee-admin never touches the DNS record; delete it in Cloudflare afterwards.

Remove site

Remove preview.lychee.land? In this order:

  1. 1.Caddyfile block removed
  2. 2.Tunnel route removed
  3. 3.Caddy validated and reloaded
  4. 4.cloudflared-sites restarted
  5. 5.preview-lychee-land.yml set to state: absent

If a step fails, the ones after it don't run.

Step 5 is what stops the container: it writes state: absent to preview-lychee-land.yml in lychee-resources, and the reconciler takes the container down on its next run, usually within two minutes.
