What to check

● caddy

Caddy keeps restarting. Every site on lychee goes through it, so all of them are down, not only this one. Its last 50 log lines usually show why:

journalctl -u caddy -n 50

Manual steps

Nothing on this page does these for you.

1

Create the DNS record, once per hostname: in the Cloudflare dashboard, add a proxied CNAME named @ pointing at the target below. Until it exists, the site can't be reached from the internet even while every check on this page passes: lychee-admin checks lychee itself, never Cloudflare.

11111111-2222-3333-4444-555555555555.cfargotunnel.com

Or, from a machine with a Cloudflare login — the host keeps no account certificate, so run cloudflared tunnel login first:

cloudflared tunnel route dns 11111111-2222-3333-4444-555555555555 lychee.land
2

Put your site's files in /var/www/lychee.land/. lychee-admin created a placeholder index.html there, which Caddy serves until you replace it.

Danger

Removing takes the site out of the Caddyfile and the tunnel route, reloads Caddy, then restarts the sites tunnel. The site's files stay unless you tick the box when you confirm. lychee-admin never touches the DNS record; delete it in Cloudflare afterwards.

Remove site

Remove lychee.land? In this order:

  1. 1.Caddyfile block removed
  2. 2.Tunnel route removed
  3. 3.Caddy validated and reloaded
  4. 4.cloudflared-sites restarted

If a step fails, the ones after it don't run.
